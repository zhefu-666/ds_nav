# 本地算法插件框架：人工验收说明

版本v1，2026-11-12。配套：[架构规格](01_ARCHITECTURE_SPEC.md)、[AI 执行说明](02_AGENT_EXECUTION.md)。

**用途：新框架实现后的逐项验收，不是当前已通过报告。** 当前没有本文约定的新CLI/插件/manifest，执行状态全部NOT_RUN。现有实车保底不因本文而切换架构。

## 1. 验收分层与人工职责

| 层级 | 验收对象 | 通过能说明什么 |
|---|---|---|
| L0 | 规格、接口、源码与权限 | 代码可审查，不能说明可编译或可运动 |
| L1 | 构建、加载、配置负例与离线回放 | 接口/计算可用，不能说明闭环导航成功 |
| L2 | 框架状态机、故障处理、唯一输出 | 运行框架行为正确，不能替算法通过路线 |
| L3 | A-E各算法组合的仿真场景 | 只证明指定模型/地图/参数/场景能力 |
| L4 | 最终Nav2独立性与回归 | 新模式职责替代完成，不能代表实车通过 |
| L5 | 后续实车准入与验收 | 另行授权、另定实车阈值，当前NOT_STARTED |

人工验收人负责核对环境、冻结门槛、选择用例、查看原始证据和判定；AI可执行已授权的仿真步骤及评分，不能自行删失败或修改准入。截图仅辅助，原始数据与有界评估结果为依据。

## 2. 环境准备与不可跳过的检查

1. 读AGENTS.md与三份规格，确认只在当前仿真环境做新框架测试。
2. 核对当前工作区修改、旧架构保底hash、原install前缀。新框架使用独立overlay和终端，不覆盖实车保底安装。
3. 记录主机/系统/ROS/Gazebo版本、CPU/GPU、实际包/库路径、源/模型/地图/profile哈希；如同时运行其他负载，性能数据标为非独占。
4. 检查domain/partition/网络及已有进程，避免与实车或其他run相连。新run继承当前项目的锁和隔离规则，不跳锁，不清理他人进程。
5. 保持当前传感器时序桥、估计器、TF、姿态和sim_command_gate；ground_truth只连接评估器，不作为定位或控制输入。只可有一个有效自动执行来源。
6. 冻结scenario清单：地图、起终点、可达性依据、碰撞体、姿态、随机种子、动态障碍轨迹、健康/倾角/间隙、物理停车阈值与持续时间、timeout。数值必须有源码/模型/评估配置来源和hash，不得临时放宽。未知项阻止该场景准入。
7. 建立不重名run目录，确认空间足够；录包topic闭包包含所有必需私人输入和frame变换。录包缺项或未正常关闭不能声明结果可复现。
8. 查看构建与仿真运行授权记录；未批准不执行。若新CLI未交付，只能做L0，不能拿旧Nav2脚本代替新框架测试。

现有参考入口（这里只说明来源，不代表本次已运行）：

- `scripts/huananhu_sim.bash`、`src/simulation_integration/huananhu_sim_bringup/launch/simulation.launch.py`：现有仿真入口。
- `scripts/sim_nav_trial.py`：现有Nav2任务结果试验，不等于真值精度评分。
- `scripts/sim_replay_evaluate.py`：已关闭bag的定位评分，不是新算法执行器。
- `scripts/sim_tunnel_mission.py`、`scripts/sim_tunnel_passage.py`：已有隧道工具，须核对实际参数和评估覆盖。
- `docs/simulation_integration/README.md`：当前说明与归档索引。旧归档脚本有绝对路径，不能直接当新队列运行。

## 3. 固定矩阵、次数与调参纪律

| profile | 搜索/规划 | 轨迹 | 控制 |
|---|---|---|---|
| A | SMAC | MINCO | MPC显式时间模式 |
| B | A* | MINCO | MPC显式时间模式 |
| C | Kastar前端 | MINCO | MPC显式时间模式 |
| D | Kastar直接轨迹 | 原生时间适配＋公共yaw | MPC显式时间模式 |
| E | SMAC | MINCO | 全向前馈＋反馈 |

新旧MPC最近点兼容模式单列迁移回归，不混入A-E。共同输入、机体约束、地图、yaw策略与评分固定；额外输入算法另列增强组。A/E做控制器离线比较时输入同一冻结轨迹；闭环比较则明确参考轨迹会因反馈而变化。

每个组合开发集最多3轮参数集试验，均留run_id。冻结后正式验收不得继续调参；失败仍保留。追加预算由用户决定。修bug不消除既有调参次数，修改哈希后重验受影响范围。

| 类别 | 每个组合的正式次数 | 必须满足 |
|---|---:|---|
| 普通路线 | 10条×3次=30 | 30/30，无禁止碰撞，位置≤0.15m，yaw≤2.5°，真实停车 |
| 指定隧道 | 每方向5次，共10 | 10/10，完整进入/通过/退出、包络与定位有效、参数恢复 |
| 指定可通行台阶 | 上下行各5次，共10 | 10/10，无禁止碰撞/失稳/包络违规、状态恢复 |
| 动态障碍 | 横穿5次、堵路释放5次，共10 | 10/10，正确避让或等待，释放后有界恢复并完成 |
| 每种故障 | 每适用插件/组合3次 | 检测、取消/拒绝/停车与证据均正确 |

在单一指定隧道/台阶模板下，五组正常场景合计至少300次；故障、负例、兼容回归和冷启动另计。若冻结清单含多座隧道/台阶，则每个声明支持的场景分别执行，不能事后只保留容易通过的一座。

不可通行负例独立评分，以明确拒绝或安全退出为通过，不能通过瞬移/穿模/人工接管算自主通过。某组合不支持该场景则列能力不足，框架分项可继续，但该组合不获完整场景准入。

## 4. 人工操作流程与命令交付要求

| 步骤 | 人工操作 | 应看到的结果 | 不通过时 |
|---|---|---|---|
| 1 | 检查profile与环境，不启动运动 | 插件/IO/能力/参数/唯一来源校验清单 | 不激活执行 |
| 2 | 获准构建后检查新overlay | 插件与依赖实际路径、构建日志 | BUILD_NOT_RUN或NEEDS_FIX，不碰旧install |
| 3 | 先运行离线固定案例 | 各算法成功/失败/超时及共同评分 | 留存失败，不先上闭环 |
| 4 | 启动隔离新仿真，保持disabled | 状态就绪、定位/TF正确、无自动运动 | 停止本run排查 |
| 5 | 对比模式接收同一输入 | 多候选输出，但无底盘接管 | 出现执行指令即框架失败 |
| 6 | 独占运行性能案例 | 搜索/优化/转换/IPC/队列/总耗时 | 超预算如实记，不追加后台堆积 |
| 7 | 显式录包，选择一个执行profile | bag路径、manifest、任务/轨迹ID | 缺录制输入则停止该实验 |
| 8 | 运行一个用例，检查事件和真实运动 | 结果满足该用例全部判据 | 保存raw/log/bag和失败原因 |
| 9 | 停用、确认物理停止、关闭bag、评分 | 候选失效、真实停止、完整评分 | 不因Action成功而忽略停车/接触失败 |
| 10 | 按冻结矩阵重复与汇总 | 全部attempt可追踪、分母不变 | 只给实际通过分项 |
| 11 | 清理本run，验证旧入口仍可独立启动 | 无本run残留，无输出冲突 | 不广泛kill、不改保底 |

## 5. 验收用例与证据

### H00：保底隔离与来源

操作：对比前后保底hash，检查domain/partition、运行包/库前缀、新模式节点/组件和输出发布者，检查新overlay终端退出后的原入口。

通过：旧入口/默认参数/比赛树/协议未变；新旧不能同时控制；新框架未连接实车。新的共享代码若必须修改，需独立批准范围与等价回归证据，不能仅凭hash差异解释通过。

### H01：插件发现与配置切换

操作：依次选择A-E并重启对应运行链，记录实际加载类/库hash；测试未知插件、非法参数、缺必需私人topic、类型/frame/schema不符、能力不兼容、重复ID。

通过：正确组合加载且输出匹配profile；错误组合明确拒绝，disabled且无有效运动指令。无静默回退，无需修改宿主源码。新增第三方算法仍允许一次编译注册。

### H02：地图/坐标/采样与Kastar适配

操作：固定小地图包含自由、障碍、膨胀、未知、边界、非零原点/旋转等用例；比较原查询与适配查询。对Kastar检查输入转换、每轴/模长上限、连续段碰撞、终点零速、yaw保持/跟随策略、时间严格递增。

通过：共同几何与可通行语义一致；D保留原生时间；C明确经过MINCO；缺yaw策略不自行补值。2D输出不自动获隧道/台阶能力。地图切换使旧map版本轨迹不可继续执行。

### H03：兼容回归与时间契约

操作：冻结状态/轨迹输入，比较旧MPC与新兼容适配；再分别运行新时间模式与第二控制器。注入不均匀采样、延迟、重复发布、乱序、NaN/Inf、任务ID改变、clock暂停/回退/重置。

通过：兼容模式的预期差异有依据；时间模式按time_from_start取样而不是最近点冒充；重复发布不续命，旧世代被拒绝，时钟重置不恢复旧任务。yaw在零速点有定义。暂停时不推进参考并按既有墙钟健康门禁停止，恢复前重新校验。

### H04：规划预算、续行与输出

操作：人工触发单次失败、连续失败、80ms超时、晚到结果、非合作worker阻塞，旧轨迹有效/无效分别测。

通过：总pipeline预算按steady计时；超预算不执行。只在有效条件下续行，从首次失败计最多0.2s，连续失败不重置。到期/不健康撤销候选；late result不复活；无无界队列/worker残留。旧轨迹和错误原因完整入日志/bag。

测量：请求接收、deadline、失败、首次续行、撤销、零指令、真实停车各自时间；20Hz调度实际周期与miss分布。指令撤销最迟下一控制tick；gate tick/失联检测另计，禁止把发布零指令视作物理停车通过。

### H05：普通导航

操作：冻结10路线覆盖起步、转弯、窄通道及最终朝向，每路线3次；使用相同地图、模型、yaw策略和约束。

通过：每组30/30；独立真值最终位置≤0.15m、wrap后yaw≤2.5°；满足冻结的实际停车速度/保持时间，无禁止接触。到达判定需要位置+朝向+停止，Action成功不足以通过。记录运动RMSE、最小间距、轨迹和运行耗时但不临时添加/放宽硬门槛。

### H06：隧道

操作：指定已知隧道的双方向各5次，覆盖接近、对齐、姿态、通过、退出、参数恢复、必要重定位与后续导航；不能只从洞内起步展示通过。

通过：全部阶段有证据；CAD包络/间隙与接触条件满足冻结定义；定位有效；控制参数和姿态退出恢复。局部穿行成功不替代完整任务成功，人工接管/传送/重置不算成功。另加不可通行包络负例。

### H07：台阶

操作：先核对模型/物理/接触确实支持定义的可通行台阶；上下行各5次，记录姿态与支撑状态。测试独立fixture不得覆盖原地图。

通过：完成、稳定、包络和支撑接触满足冻结条件；正常轮地/允许支撑接触不误判为碰撞，机身违规接触不放过。若模型不支持，标BLOCKED_EXTERNAL，不能改碰撞体穿模或直接忽略测试。

### H08：动态障碍

操作：固定障碍几何、轨迹、速度和触发条件，横穿5次、堵路后释放5次。记录感知输入及障碍真值，真值只进入评估。

通过：无禁止碰撞，横穿正确避让/等待；堵路时不硬闯，释放后在冻结timeout内恢复并到达。轨迹不支持动态预测时如实标记策略能力，不用瞬时地图绕行成功宣称具备预测。

### H09：异常矩阵

每种适用故障3次；加载与接口故障可在静止/离线做，运动相关故障需正式仿真。公共框架用例可共享证据，但每个插件的取消/超时/异常退出均须覆盖。

| 故障 | 应观察到的结果 |
|---|---|
| 定位valid=false / 心跳过期 / odom过期 | 按冻结健康定义撤销运动，旧轨迹不续行 |
| NaN、frame错误、时间乱序、缺私人输入 | 拒绝无效数据，不伪造有效状态 |
| 无路、规划超时、优化失败 | 区分原因，执行H04续行/停车策略 |
| 规划worker崩溃或不合作 | 控制不被阻塞，超时不执行晚结果，worker有界回收 |
| 控制器崩溃/失联 | gate按既定看门狗停车，保存检测时延，不声称下一tick已检测进程死亡 |
| 任务取消、抢占、新旧结果交叉到达 | 旧世代失效；取消不进入续行，抢占不能复活旧任务 |
| 人工接管、切回自动 | 来源唯一，自动恢复需明确状态/任务，不直接执行缓存 |
| clock暂停、回退、重置 | 按H03处理；wallclock和simtime分别记录 |
| map切换、节点停用/重启 | 旧轨迹和旧地图任务不得未经确认恢复 |
| 磁盘不足、bag缺topic或未关闭 | 停止该实验，证据无效，保留错误，不产出假PASS |

### H10：日志、回放与清理

操作：关闭bag后重新评分；从记录重建公共与私人输入；核对旧轨迹、超时、切换、错误及停车事件。检查输出目录是否被复用、CSV是否截断覆盖，清理仅针对run拥有的进程。

通过：manifest可关联所有数据与尝试；缺样本/覆盖率计入结果，不排序掩盖时间回退，不只挑成功片段；无本run残留发布者/worker/锁。日志能回答“当时输入什么、执行哪条轨迹、为什么切换/停车”。

### H11：最终独立性

操作：按AI说明T9检查活动进程、Action/readiness、构建声明、头文件、导出插件与实际加载库，复验所有受影响A-E场景。

通过：最终模式无Nav2导航宿主；公共契约与核心插件无Nav2接口依赖，地图和任务必要职责均承接。仍有过渡依赖则单列NEEDS_FIX，即使其他框架功能已通过也不宣称完成去Nav2。

## 6. 结果包与判定方式

建议每次run保存：

```text
<run_id>/
  manifest.json               # 组合、哈希、命令、环境、权限、场景和冻结门槛
  resolved_profile.yaml
  events.jsonl                # ID、原因、sim/steady时间、轨迹切换
  raw/                        # 状态、候选/执行轨迹、计算和控制统计
  bag/                        # 正常关闭的bag与metadata
  evaluation.json             # 独立评分、coverage、各判据
  cleanup.json                # 停用/停车/残留进程检查
  summary.md                  # 人能读懂的结果及失败定位
```

汇总至少分开这些字段，不使用一个绿色PASS覆盖全部：

```json
{
  "framework": "NOT_RUN",
  "runtime_independent": "NOT_RUN",
  "dependency_independent": "NOT_RUN",
  "profiles": {"A": "NOT_RUN", "B": "NOT_RUN", "C": "NOT_RUN", "D": "NOT_RUN", "E": "NOT_RUN"},
  "real_robot": "NOT_STARTED"
}
```

PASS只用于完成且证据齐全的分项；NEEDS_FIX用于代码/行为/证据不满足；BLOCKED_EXTERNAL用于可明确举证的模型或外部缺项；NOT_RUN/BUILD_NOT_RUN不能改写成PASS。重复失败不能从分母删除，修复后的新套件保留旧失败和新哈希，分别报告。

**完整仿真交付**要求：框架、接口、最终独立性通过，A-E每个声明支持的必测场景均完成。若某组合或台阶模型未通过，可交付已验证部分，但总体不称全部完成。实车候选只从对应场景已通过的组合选择。
