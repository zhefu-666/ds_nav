# 基础导航串口 V1 交付与联调

本次交付覆盖固定朝向下的前后、左右平移。启动前将底盘前向与 `camera_init` 的 X 正轴对齐，整个试验保持该朝向。MPC 的速度参考系应为实车默认配置中的 `camera_init`。这个模式使用零航向，所以直接取 `/cmd_vel_mpc` 的 X/Y 速度，角速度固定发零。

## 串口对接

| 项目 | 当前实现 |
|---|---|
| 设备 | 默认 `/dev/ttyACM0`，115200 baud，8N1 |
| 导航 → STM32 | `0x6B`，15 字节，含底盘前向、左向目标速度和零角速度 |
| STM32 → 导航 | 本轮无回传依赖 |
| 发送周期 | 20 ms，标称 50 Hz |
| 上位机超时 | 最后一次有效 MPC 指令满 100 ms 时，发送改为零速。调度对齐到下一个发送周期 |
| STM32 超时 | 电控须实现独立 100 ms 看门狗，仅合法速度帧刷新。由电控联调验证 |

线缆布局详见[协议 V1](BASIC_NAV_SERIAL_PROTOCOL.md)。便于抓包核对的联调向量如下。

| 指令 | 预期串口字节 |
|---|---|
| 三轴零速 | `6B 00 00 00 00 00 00 00 00 00 00 00 00 7A C5` |
| X 为 1 m/s，Y 为 −0.5 m/s，角速度被固定为零 | `6B 00 00 80 3F 00 00 00 BF 00 00 00 00 71 CD` |

## 启动

完成构建并载入该工作区环境后，启动原实车导航链路，再单独启动基础导航串口。

```bash
source install/setup.bash
ros2 launch communication basic_nav_serial.launch.py
```

串口不同可追加 `port:=/dev/ttyACM1`。运行前确认 `com.launch.py`、`start.bash` 启动的比赛串口节点及其他同串口程序均已停止。新节点打开端口后请求 Linux TTY 独占，运行前仍要检查已持有端口的进程。接上 STM32 前，先用抓包端验证启动零速、速度字段和 CRC。

## 实车验收

1. 确认 STM32 按 `0x6B`、15 字节和 Dust CRC16 解码，角速度为零时底盘禁止主动转向。
2. 在抬轮或受控低速条件下分别验证正、负 X/Y，确认前后和左右方向、速度单位。开始前摆正车头。
3. 停止 MPC 指令，核对上位机恢复发送零速的时间。另行拔串口或结束串口节点，核对 STM32 独立超时停车。
4. 重连后核对首个完整帧为零速，后续运动来自重连后新到达的 MPC 指令。
5. 若车身在联调中偏转，停车并重新摆正。转向导航需要后续接入随车身更新的航向。
